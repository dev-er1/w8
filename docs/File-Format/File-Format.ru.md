## Порядок байт
Все многобайтовые целочисленные значения в формате W8 Bytecode хранятся в порядке байт **Little-Endian**.

---

## Структура файла в формате W8 Bytecode
| Смещение   | Размер   | Секция     |
|:----------:|:--------:|------------|
| 0          | 5 байт   | Magic      |
| 5          | 6 байт   | Версия W8  |
| 11         | —        | Байткод    |

---

## Magic сигнатура
Первые 5 байт файла должны быть:
```text
4E 56 4D 42 43
```
(`NVMBC`)

Это позволяет определить, что файл содержит байткод W8.

---

## Версия W8
Сразу после magic-сигнатуры располагаются **6 байт**, определяющие версию W8, с которой был скомпилирован файл.

Версия хранится в виде трёх последовательных значений типа `u16`.
```text
<u16><u16><u16>
```

Версии W8 несовместимы друг с другом: версия, указанная в файле, должна в точности совпадать с версией виртуальной машины. Иначе загрузка
файла должна быть прервана с ошибкой о несовместимости версий.

---

## Байткод
После заголовка файла идёт поток инструкций. Каждая инструкция кодируется следующим образом:

### Кодирование инструкции
```
[опкод: u8]                  — OperationCode (см. opcode.rs)
[количество_операндов: u8]   — число операндов, 0–3
[операнд₁]                   — если количество ≥ 1
[операнд₂]                   — если количество ≥ 2
[операнд₃]                   — если количество ≥ 3
```

### Кодирование операнда
Каждый операнд начинается с тега (1 байт), за которым следуют данные:

| Тег | Тип        | Данные                                   |
|:---:|------------|------------------------------------------|
| 0x00 | Register   | 1 байт — номер регистра (`u8`)          |
| 0x01 | Immediate  | 8 байт — значение (`u64` Little-Endian) |
