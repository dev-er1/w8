# Контрибьютинг W8

Во-первых: спасибо за интерес к W8! Я рад, что вы хотите внести свой вклад в проект.
Ниже приведены инструкции о том, как вы можете помочь.

## Как внести свой вклад
1. Ознакомьтесь с [документацией](docs/Architecture/Architecture.ru.md).
2. Найдите проблему, которую вы хотите решить, или функциональность, которую хотите добавить.
3. Если изменение затрагивает архитектуру W8, ISA или формат байткода, создайте issue для его обсуждения до начала работы.
4. Создайте форк репозитория и новую ветку для вашей работы.
5. Внесите изменения.
6. Убедитесь, что код проходит CI и все тесты.
7. Если изменения затрагивают поведение W8 или её архитектуру, обновите документацию.
8. Отправьте Pull Request с описанием внесённых изменений.

## Pull Request
Pull Request должен содержать:
- краткое описание изменений;
- описание проблемы, которую решает изменение;
- тесты для новой функциональности или исправлений, если это возможно;
- обновление документации, если изменилось публичное поведение W8.

Старайтесь не смешивать несколько несвязанных изменений в одном Pull Request.

## Стиль кода
Перед отправкой Pull Request убедитесь, что код соответствует стандартам проекта. Для локального запуска CI запустите любой из
этих скриптов ниже (под ваш shell):
- [CI скрипт на PowerShell](scripts/ci/ci.ps1);
- [CI скрипт на Sh](scripts/ci/ci.sh)

## Написание документации
При написании документации (в коде или в документах) желательно не использовать разговорные выражения.

Писать комментарии в коде нужно только на **английском**.

## Issues
- Сообщение об ошибке:

    При создании Issue с ошибкой укажите:
    - описание проблемы;
    - шаги для её воспроизведения;
    - ожидаемое поведение;
    - фактическое поведение;
    - опционально, скриншот, где вы видите ошибку;
    - версию W8.

- Предложение функциональности

    Опишите:
    - какую проблему решает предлагаемая функциональность;
    - предполагаемое поведение;
    - при необходимости — пример использования.
